# 2.0 alpha.2 checklist

Alpha.1 is closed at commit `d2e9135`. This branch is the working line for
remaining adjustments before the stable 2.0.0 freeze.

## Inherited from alpha.1

- [x] Xcode 27 / Swift 6.4 migration and iOS 17 deployment contract.
- [x] Snapshot, performance, Gallery smoke, DocC, coverage, API, and consumer
      checks completed locally.
- [x] Plan remains excluded from Git.
- [x] API baselines remain unchanged; no regeneration is required for alpha.2.

## Alpha.2 work rules

- [ ] New adjustments are allowed while alpha.2 is active.
- [ ] Every behavioral or rendering change adds or updates a test.
- [ ] Intentional public API changes are called out in the changelog and migration
      guide; do not regenerate a baseline merely to make a check pass.
- [ ] Rerun the full Xcode 27 suite, iOS 17.5 lane, coverage, DocC, consumer,
      performance, and visual suites before tagging alpha.2.
- [ ] Tag `v2.0.0-alpha.2` only from the approved candidate SHA; the workflow will
      create a draft pre-release.

## Stable freeze remains later

The `v2.0.0` tag, stable API baseline decision, protected merge to `main`, and
post-release smoke window belong to the final release phase, not alpha.2 setup.

## Alpha.2 image/button adjustment work

- [x] `DSRemoteImage` preserves the default skeleton/shimmer and error
      placeholder, with optional custom loading content and a loading-to-success
      transition that respects Reduce Motion.
- [x] Existing `DSRemoteImage` examples, previews, Gallery, snapshots, public
      API compilation, migration notes, README, and changelog are updated.
- [x] The additive `DSRemoteImage` initializer is reviewed and recorded in the
      2.0.0 API baseline.
- [x] `DSButton` remains unchanged: regular stays full-width by default, and
      no width API or snapshot migration is introduced.
- [x] SwiftLint, iOS 27.0 tests, iOS 17.5 minimum-runtime tests, coverage,
      DocC diagnostics, API check, scripts, and external consumer pass.
- [ ] Create a release tag only after the user approves the candidate; this task
      intentionally does not create one.
